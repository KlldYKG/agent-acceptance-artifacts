# RQ1-flash 批分析报告（A0 基线，Linux 云端全批）

批次：2 agent × deepseek-flash × A0 臂 × 5 链 × 3 重复 = **30 次链运行 / 300 任务实例**。
执行：阿里云 ECS（Ubuntu 24.04），2026-11-17 13:12 启动，opencode 18:50 收官、aider 11-18 凌晨收官，**零 FAIL，零无效运行**。

## 一、头条发现

### 1. agent 架构差距远超预期：73% vs 23%

| agent | TCR（任务通过率） | 成本 | 计算 |
|---|---|---|---|
| **opencode**（迭代式 agent，可自跑命令自检） | **110/150 = 73.3%** | $1.88（sqlite 精确值） | 5.7 h |
| **aider**（`--message` 单轮模式，一次性改完不回看） | **34/150 = 22.7%** | ≈$12.4（token 估算） | 12.8 h |

aider 分链：A 87.5%、B 18%、C 7%、D 12%、E 3%——除 A 链（httpx，任务最简单）外全面崩溃。抽查确认：REJECT 均为真实失败（gold holdout 测试跑出具体失败节点），aider 会话均值 126k 入/55k 出 token，**它在认真干活但改不对**。
解读：单轮"盲改"与迭代式 agent 的差距是**架构级**的，这本身是可写进论文的发现（自检回路比模型价格更重要）；对 RQ1 的威胁分析须注明两 agent 不是同构对比。

### 2. 链内序位衰减真实存在，但形态依链而异（opencode 侧）

| 链 | 前段（任务 1–4） | 后段（最后 3 位） | 形态 |
|---|---|---|---|
| A（httpx） | 100% | **0%（pos8 悬崖）** | 悬崖式 |
| B（marshmallow） | 100% | 33%→33%→**0%** | 标准衰减曲线 |
| C（sqlparse） | 33–100% 波动 | 67%→**0%** | 高难度+噪声 |
| D（click） | 75–100% | **0%→0%** | 震荡下行 |
| E（black） | 83–100% | 100%/100%/100% | 无衰减（任务太易） |

**结论**：五链中三链（A/B/D）出现清晰的后段崩溃，C 高难震荡，E 全程地板通过。"AI 链式任务质量衰减"核心假设在 flash 档获得**方向性支持**，衰减幅度与链难度交互——这正是 RQ1 要刻画的现象，数据足够支撑 workshop 级叙事。

### 3. 成本大幅低于校准外推

- opencode 单链运行实测 **$0.125**（校准期 $0.187，低 33%）→ 后续阶段成本全部下调；
- aider 贵 6.6 倍（$12.4/15 场），坐实"阶段 2/3 只用 opencode"的纪律；
- **全批实际 ≈ $14.25 ≈ ¥103**（预估 ¥76，+35%；含本地已花 ≈¥2，项目累计 ≈¥105，距 ¥300 上限余量 ≈¥195）。
