## 2. 变异触达漏斗（本批实测）

```
63 任务
 └─ 6 任务产出测试文件（9.5%；57 个"测试缺位"任务门控无输入，与 RQ2 缺位率 91.3% 一致）
     └─ C1 ×3：变异启动 → 300s 预算 TIMEOUT（诚实降级，无分数）
     └─ D1 ×3：mutmut 启动 → 基线被 agent 破损测试顶停 → 0 突变体可测
 └─ 批内变异分数产出：0/63
```

**三层约束，逐层递进**：

1. **上游缺位**（90.5%）：agent 只改实现不改测试时，变异根本没有检查对象——变异覆盖率的上限被 RQ2 发现的失效模式锁死。
2. **CI 预算**：C1（sqlparse，单改动文件 800+ 突变体）300s 不可完成，junitxml 对未完成 run 拒绝输出部分结果 → 只能诚实 TIMEOUT。
3. **基线质量**：D1（click）agent 写的 12 个新测试中 2 个破损（在 head 上确定性失败）。门控正确判 `INVALID_EVIDENCE/NONE`；mutmut 基线要求全文件绿，被同一批破损用例中止。**变异需要绿基线，而"agent 测试是否有破损"恰恰是被测变量**——这是机制层面的耦合，不是工程事故。

## 4. 运行环境修复记录（不影响 A0/A1 历史数据，均未执行过变异相）

- 任务 venv 安装 mutmut==2.5.1 ×5（首跑批 SKIPPED 的根因之一：引擎缺失）。
- 门控 `run_mutation` 的 `Path.resolve()` → `abspath`：venv python 是符号链接，resolve 会逃逸到系统 python（无 mutmut）。
- mutmut 配置 runner 裸 `python` → 绝对路径插值。
- **mutmut 2.5.1 + toml 0.10.2 对 PEP-621 pyproject.toml（数组内嵌 inline table）抛裸 IndexError** → 已给 5 个任务 venv 的 mutmut 配置加载补异常捕获（`FileNotFoundError, KeyError, TomlDecodeError, IndexError` → 回退 setup.cfg）。sqlparse（无 pyproject）不受影响，click/httpx/black/marshmallow 均会命中。
- 待办（v1.0.1）：`parse_mutation` 对"基线失败后 junitxml 输出 0 用例"应降级 SKIPPED，而非 OK/0/0（当前语义有误导性）。

## 5. 对 arXiv:2609.09315 成本质疑的回答（论文口径）

该文质疑变异测试的成本收益。我们的实证答案不是"有用/没用"，而是**边界条件刻画**：

> 在真实 PR 形态的任务上，变异检查的增量价值受三层约束：测试缺位率（90.5%）决定触达上限；CI 预算（300s）决定大文件任务不可完成；agent 测试的破损率决定基线可用性。三层全过之后（预算 900s、基线干净），变异可完整运行，但强测试下增量信号为零。因此变异宜作为**可选的深度检查层**（预算充足时运行），而非默认门控路径；其"诚实降级"语义（TIMEOUT/SKIPPED 不伪造分数）保证了该结论在任何预算下都不被污染。

配套机制发现：**破损 agent 测试同时阻断两个检查器**（门控判 INVALID_EVIDENCE、mutmut 基线中止）——证据有效性检查（fail-before→pass-after）与变异检查共享同一前置条件"测试本身是绿的"，这是双向有效性机制作为变异前置门的直接证据。

## 6. 交叉观察（计划外，但有论文价值）

D1 在两臂中均被 runner 接受（金测试通过），而门控判 INVALID_EVIDENCE（含 2 个破损测试）。即：**金测试验收通道对"agent 新增测试本身破损"存在盲区**，6 个产测试任务中 3 个（D1×3）命中。这为报告模式工具的价值提供了补充证据：它检测的是金测试看不见的质量维度。
