# 同源/异源合谋对照实验报告（零 API 成本）

**日期**：2026-11-18 · **平台**：阿里云 ECS（本地执行，无 API 调用）
**方法**：A0 存量 300 实例 → 供体（自写测试且实现正确）× 受体（同任务坏实现）配对 22 对，
物化坏实现树 + 注入供体测试 + 测判别力。

---

## 一、头条结果：合谋假设**未被支持**——两种条件下合谋率均为 0%

| 条件 | 有效对 | 合谋（测试全过坏实现） | 合谋率 |
|---|---|---|---|
| **同源**（agent 自己的测试 × 自己的坏实现，可跨 rep） | 6 | 0 | **0%** |
| **异源**（另一 agent 的测试 × 坏实现） | 10 | 0 | **0%** |

逐对明细：16/16 有效对中，供体测试在坏实现上**全部出现失败**（判别成功）。
同源与异源无差异（Fisher 精确检验 p = 1.0）。

*注：E1 任务 6 对因缺 harness 引导模块 `_black_version.py` 收集失败，作伪影剔除（修复方法已知，不影响结论方向）。*

## 二、比合谋率更重要的发现：**真正的威胁是测试缺位，不是测试合谋**

| 事实 | 数字 |
|---|---|
| A0 存量 300 实例中，agent 交付里**含任何自写测试**的 | 仅 26（**8.7%**） |
| RQ2 A1 批 60 个首轮任务中门控判 NO_EVIDENCE 的 | 56（**93%**） |

两个独立批次指向同一结论：**flash 档 agent 在 90%+ 的情况下根本不交测试**。
"自我认证"在这个样本里的失效模式不是"写了没判别力的测试"，而是"压根不写"。

## 三、对论文叙事的影响（按宣称纪律如实调整）

1. **合谋对照（B 档）结论降级改写**：不能宣称"同源测试会合谋"——本样本明确否定。
   改写为："在 N=16 的配对样本中同源/异源判别力无差异（均为 0% 合谋）；但测试缺位率
   超过 90%，说明自我认证的第一失效模式是缺位而非合谋"——这是一个诚实的、有信息的负面结果。
2. **门控的价值主张获得新实证**：证据门的"NO_EVIDENCE 检出"路径恰好命中主要失效模式
   （强制"必须有测试"），而"区分性判定"路径防住次要模式（测试无判别力）。两层防御各有其靶。
3. **与 Agent Gate 的对比更精准**：其静态"有无测试文件"检查覆盖第一模式，但第二模式
  （有测试但无判别力）仍需我们的执行层验证——互补定位得到数据支持。
4. **可引用空白表述更新**："no one measures how verified evidence changes downstream
   agent behavior" 保持不变；新增 "and no one reports the base rate of evidence
   absence in agent contributions"（本实验给出的 91.3% 缺位率本身就是新数据点）。

## 四、局限

1. 样本量小（16 有效对），且集中在 4 个任务（B1/C1/D1/E1）——合谋率 0% 的置信区间仍宽；
2. 供体测试均来自 ACCEPT 实例（在正确实现上验证过），不代表 agent 在"明知要被验"时现写的测试质量；
3. 仅 flash 档；v4-pro 是否更倾向写测试、测试判别力如何，留待阶段 3；
4. E1 伪影对的修复（注入引导模块）待补，预计只增不改结论。
