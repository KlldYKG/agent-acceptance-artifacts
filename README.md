# agent-acceptance — Experiment Artifacts

Artifact package for the paper *"An Acceptance Gate for AI-Contributed Tests:
Bidirectional Validity and Mutation-Based Evidence"* (preprint title, see the
LaTeX source in the paper submission package for the final title).

Tool repository: https://github.com/KlldYKG/agent-acceptance (v1.0.1)

## What this package contains

| Directory | Contents | Size |
|---|---|---|
| `dataset/` | 5 task chains (A–E) with gold tests, chain scaffolds, quality-check scripts and pilot reports; `REPOS.md` lists the pinned upstream commits | ~200 KB |
| `harness/` | Experiment harness: chain runner, agent adapters (aider / opencode), gate invocation, V-round checks, figure scripts | < 1 MB |
| `runs/` | Raw execution logs for all reported runs (RQ1/RQ2 flash runs, A-full ablation, v4-pro baseline): `chain_log.json`, per-task transcripts, diffs, gold results | ~13 MB |
| `figures/` | The three figures used in the paper (regenerated by `harness/make_figures*.py`) | ~400 KB |
| `analysis/` | Chinese-language analysis reports (RQ1/RQ2/RQ3, V-round validation, collusion contrast, cost calibration, design notes) and batch launcher logs | < 1 MB |

Nothing in this package contains secrets: all API credentials were supplied at
run time via the `DEEPSEEK_API_KEY` environment variable and are never written
to logs. A targeted scan (key-shaped strings: `sk-…`, `ghp_…`, `AKIA…`,
`*_API_KEY=…`) over every published file returned zero matches.

## Reproducing a chain run

1. Install the gate: `pip install agent-acceptance==1.0.1` (or clone the tool
   repository and `pip install -e .`).
2. Clone the six upstream repositories at the pinned commits (`dataset/REPOS.md`).
3. Create one virtual environment per task chain; the harness scripts in
   `dataset/` (see `dataset/HARNESS_GUIDE_CN.md`, in Chinese) document the
   expected layout, including the `mutmut==2.5.1` + `toml==0.10.2` pin used by
   the mutation phase.
4. Export `DEEPSEEK_API_KEY`, then run the chain runner (`harness/runner.py`)
   with `--adapter aider|opencode` and the desired model.

Raw outcomes for every run reported in the paper are in `runs/`; each run
directory carries a `chain_log.json` with per-round verdicts, gate reports and
token-cost details, plus per-task transcripts and patches.
